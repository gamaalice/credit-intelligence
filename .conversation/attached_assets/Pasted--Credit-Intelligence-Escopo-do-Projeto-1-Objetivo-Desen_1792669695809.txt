# Credit Intelligence — Escopo do Projeto

## 1. Objetivo

Desenvolver uma solução de Machine Learning para estimar a probabilidade de inadimplência de clientes, demonstrando competências em Python, PySpark, SQL, análise de dados, treinamento e avaliação de modelos.

O projeto será desenvolvido para portfólio, com dados públicos e finalidade exclusivamente educacional. Não será utilizado para tomar decisões reais de crédito.

## 2. Escopo funcional e técnico

### 2.1. Dados e análise exploratória
- Utilizar o dataset público Default of Credit Card Clients, disponibilizado pela UCI Machine Learning Repository.
- Documentar a origem, as variáveis, a variável-alvo e as limitações dos dados.
- Realizar análise exploratória, verificar valores ausentes, duplicidades, distribuição da variável-alvo e possíveis inconsistências.
- Não inventar dados, resultados ou características do dataset.

### 2.2. Processamento de dados
- Utilizar Python, Pandas e NumPy na análise e preparação dos dados.
- Utilizar PySpark para implementar transformações e agregações efetivas sobre os dados.
- Utilizar SQL para consultas analíticas, segmentações e cálculo de indicadores.
- Separar os dados de treino e teste antes de ajustar transformações que possam causar vazamento de dados.
- Documentar as decisões de limpeza e preparação.

### 2.3. Machine Learning
- Desenvolver um modelo de referência com Logistic Regression.
- Comparar o modelo de referência com Random Forest e Gradient Boosting, utilizando implementações do Scikit-learn.
- Utilizar pré-processamento adequado a cada algoritmo.
- Tratar o desbalanceamento da variável-alvo quando necessário, sem contaminar os dados de teste.
- Avaliar os modelos com precision, recall, F1-score, ROC-AUC e matriz de confusão.
- Definir o modelo final com base em critérios documentados, não apenas na acurácia.
- Verificar a calibração das probabilidades e analisar a influência das variáveis quando tecnicamente aplicável.

### 2.4. API e visualização
- Criar uma API com FastAPI para disponibilizar as previsões do modelo selecionado.
- Validar os dados de entrada e retornar a probabilidade estimada e os metadados pertinentes.
- Criar um dashboard em Streamlit para apresentar métricas, distribuição das previsões e comparação dos modelos.
- Não apresentar previsões como certezas nem como decisões definitivas de crédito.

### 2.5. Qualidade e reprodutibilidade
- Criar testes para as principais transformações, o treinamento e os endpoints.
- Fixar e documentar as dependências.
- Fornecer instruções para configurar o ambiente, executar o pipeline, treinar o modelo, iniciar a API e abrir o dashboard.
- Incluir Docker para facilitar a reprodução do ambiente.
- Registrar os experimentos e parâmetros com MLflow, desde que a integração permaneça compatível com a implementação.
- Não exigir serviços pagos, credenciais externas ou APIs comerciais.

## 3. Tecnologias obrigatórias

Python, Pandas, NumPy, PySpark, SQL, Scikit-learn, FastAPI, Streamlit, pytest e Docker.

MLflow será utilizado para rastreamento de experimentos.

## 4. Fora do escopo

- Uso de dados pessoais reais ou dados privados.
- Integração com bureaus de crédito ou serviços comerciais.
- Decisões automatizadas reais de concessão ou recusa de crédito.
- Interface web complexa, autenticação, cadastro de usuários ou sistema financeiro completo.
- Treinamento de redes neurais ou modelos generativos.
- Infraestrutura em nuvem paga, processamento distribuído em cluster ou deploy obrigatório.
- Funcionalidades que não contribuam diretamente para demonstrar os requisitos da vaga.

## 5. Critérios de conclusão

O projeto será considerado concluído quando:
1. O dataset e suas limitações estiverem documentados.
2. O processamento Python/PySpark e as consultas SQL estiverem implementados.
3. Os três modelos forem treinados e comparados com avaliação reproduzível.
4. O modelo selecionado puder gerar previsões por meio da API.
5. O dashboard apresentar os resultados reais dos experimentos.
6. Os testes essenciais forem executáveis.
7. A documentação permitir reproduzir a execução local.
8. O repositório estiver organizado e pronto para apresentação em portfólio.
